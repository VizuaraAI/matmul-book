How a Matmul Kernel Gets Fast

Ten kernels take one matrix multiply from 1.3% of the hardware to 93.7%. This book animates every step: where the bytes go, where the instructions go, and why each rewrite changes the number.

After Simon Boehm's CUDA matmul worklog · every measurement his, on an NVIDIA A6000 · a sequel to The CUDA Programming Model

Multiplying two matrices is the most-run operation in machine learning, and on a GPU the obvious way to write it uses about one percent of the chip. Getting to ninety-three percent takes ten rewrites of the same forty lines. None of them changes the arithmetic. Every one of them changes how numbers travel: from the memory chips, through the caches and the shared scratchpad, into registers, and finally into the units that multiply.

That is a story about movement, and movement is hard to follow in still pictures. So this book is built out of animations. Each chapter takes one kernel (or one idea the next kernel needs) and shows it running: tiles leaving global memory, sectors arriving whole whether you wanted them or not, a warp's 32 threads asking for 32 addresses at once, a register holding sixteen numbers and producing sixty-four multiply-adds. The prose explains; the animation is the argument.

How to read this book

Every animation plays on its own when it scrolls into view, and loops. Under each one is a caption that changes as the animation moves: that caption is the narration, and the numbered steps are the real structure of the argument. Use the ⏮ ⏭ buttons (or the arrow keys, after clicking an animation) to move one step at a time, and drag the slider to scrub. Nothing is a video; every frame is computed, so you can stop anywhere and read the numbers off it.

The numbers are real. The small matrices are an actual 8 × 8 integer product, the byte counts follow from how DRAM serves 32-byte sectors, and the speeds are Simon Boehm's measurements. Where the book predicts a speedup from first principles and then quotes the measurement, both numbers are given so you can see how close the reasoning lands.

Contents

Three foundation chapters, then one chapter per kernel. Percentages are each kernel's speed as a fraction of cuBLAS, NVIDIA's own library. If you already know what a warp and a sector are, start at chapter 4.

Built by Vizuara, September 2026. Route and measurements: Simon Boehm, How to Optimize a CUDA Matmul Kernel for cuBLAS-like Performance: a Worklog, and the SGEMM_CUDA repository. Hardware model: Stephen Jones, How CUDA Programming Works (GTC 2022), and the CUDA C++ Programming Guide. The animations are plain SVG driven by a small timeline engine; there are no videos and no external libraries.
